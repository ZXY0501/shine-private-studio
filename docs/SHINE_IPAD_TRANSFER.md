# 从 iPad 送到 SHINE：本地试用版

## 先说现在能用什么

新版本提供独立的“素材收件口”页面 `inbox.html`。它负责把原始 PSD / PNG 送到你自己的临时收件箱，不会自动替换订单，不会改色，也不放进共用素材库。

这不是完整版 iPad 工作台，也还没有安装到你 iPad 上的苹果快捷指令。正式站和阿里云必须一起更新后，iPad 才能使用正式收件服务。电脑本机的 `127.0.0.1` 地址在 iPad 上不是这台电脑。

当前电脑端支持将头发 PSD 按指定订单和 A / B 临时接入。其他 PSD / PNG 可以从收件箱下载原件，再通过现有上传入口使用；暂不承诺所有类别直接接入。

## 最容易测试的一条路

1. 在 Procreate 画好：操作 → 分享 → PSD（要分层改色）或 PNG（不改色的小物）。
2. 先选择“存储到文件”，存到自己能找到的位置。
3. 用 iPad Safari 打开 SHINE 的 `inbox.html`，确认后端地址，登录自己的独立账户。
4. 勾选临时保存说明，选择刚才的文件，点“发送待传素材”。发送时保持页面在前台。
5. 出现“已送达收件箱”后，到电脑的收件区刷新，确认订单、A / B 和用途，再接收。

这条路已经不需要微信，但还保留了一次“存到文件 → 选择文件”。下一步真正要砍掉的就是这一步：在你的真实 iPad 上配置和验证分享快捷指令。

## 不想在 iPad 登录账户时

在电脑收件区创建一个“仅上传设备令牌”，命名为例如“我的 iPad”。令牌只显示一次，在 iPad 收件口切到“仅上传令牌”粘贴。

- 它只能发送这台设备的文件，不能浏览素材、订单或管理账户。
- 默认有效期 30 天，可在电脑撤销；账户禁用或删除也会失效。
- 不要填管理员总口令、DeepSeek Key 或云服务密钥。
- 凭据只保留在当前标签页的会话存储；退出连接会清除。浏览器恢复标签页时可能恢复会话，要清除请使用“退出连接”。
- 不要把含令牌的链接、截图或快捷指令分享给朋友；朋友用自己的账户和令牌。

## 文件保存多久、失败怎么办

- 一个文件最多 200 MiB，临时收件箱当前上限 30 条、合计约 1 GiB。
- 每条记录从首次创建起有效 48 小时，重试不会重置时间。
- 过期即不能再通过收件箱下载。当前物理清理在后续访问时进行，并不是第 48 小时整自动删；要马上清理可在电脑删除。
- 本服务还没有部署云端定时清理任务。少量编号和撤回标记会保留，用于防止旧请求把删除记录恢复；源 PSD / PNG 不包含在这些标记里。
- 出现失败请点原记录的“重试”，不要反复建立新发送；丢失确认时会先查原记录。
- 刷新网页后，未完成的文件需重新选择同一份，已保留的发送编号用于继续。
- “移出本页记录”只清理手机页面记录，不删除云端文件。
- 原始 Procreate 稿件请自己保留，这里不是长期备份盘。

## 给开发者：苹果快捷指令接入契约

快捷指令需要接收分享菜单传入的文件。每个文件使用独立 `clientRequestId`，在同一次失败重试中保持不变。凭据只放在请求头，不放 URL。后端地址必须是可信 HTTPS 地址。

### 1. 申请上传地址

`POST /api/inbox/upload-ticket`，JSON 请求头 `Content-Type: application/json`，认证头 `Authorization: Bearer <仅上传设备令牌>`。

请求体字段：`fileName` 为含 `.psd` / `.png` 后缀的文件名；`size` 为准确字节数；`contentType` 为 PSD 的 `image/vnd.adobe.photoshop` 或 PNG 的 `image/png`；`clientRequestId` 为长度 8～128 的唯一字符串（字母、数字及 `_.:-`）。

响应包含 `id`、`item`、`uploadUrl`、`uploadHeaders`、`receipt`。若 `item.status` 已是 `READY` / `RECEIVED`，这就是原发送已完成；不得再次上传。否则保存 `id` 和 `receipt` 供这次发送确认使用。

### 2. 上传文件原始字节

对响应里的完整 `uploadUrl` 发 `PUT`，请求体是文件本身，不是表单、JSON、Base64 或压缩包。请求头只用 `uploadHeaders` 的 `Content-Type`。**不要向云存储地址转发 SHINE 的 Authorization 头。**

### 3. 确认上传

`POST /api/inbox/<id>/complete`，认证头同第 1 步，JSON 请求体为 `{ "receipt": "第1步的原始receipt" }`。只有确认返回 `item.status = READY` 或 `RECEIVED` 后才显示发送成功。上传或确认超时先重试此确认；如果返回上传尚缺失或上传票据过期，再沿用原 `clientRequestId` 回到第 1 步。

### 4. 验收范围

先用一个小 PNG，再用一个真实头发 PSD；测试取消、断网重试、重复点击、电脑切换订单、A / B 接收、原色保留。实际 iPad 的分享菜单名称和快捷指令动作配置需要现场验证；此文档没有生成或安装 `.shortcut` 文件。

## 部署前检查

- 后端、移动页和电脑页要是同一版本；新后端包含 Inbox、Handbook、两个 OSS store 及共享 `color-handbook.js`。
- 用 `node backend/package-release.js --with-dependencies` 可生成新的独立后端目录，不覆盖旧包，不读取 `.env`，不上传。生产密钥继续留在阿里云环境变量。
- `ALLOWED_ORIGIN` 使用实际前端 origin，如 `https://zxy0501.github.io`，不是含项目路径的完整 URL。
- OSS 保持私有，为该前端 origin 放行 `PUT` / `GET` / `HEAD` 和上传使用的 `Content-Type`。后端自身的 CORS 不等于 OSS 直传 CORS，两处都要验证。
- 云端定时物理清理、事务级配额以及真实 iPad 分享快捷指令，仍是上线/后续强化事项，不能用单元测试代替。
